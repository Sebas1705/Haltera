## Feature module contract

Every `feature:<name>` module:

- Depends only on `core:*` and `domain:usecases` (which exposes `data:models` and the `data:repository`
  interfaces). Never on another feature, `data:local` or `composeApp`. The build file already lists them.
- Exposes exactly three public things, which the shell (`composeApp/navigation/MainShell.kt`,
  `composeApp/di/AppModule.kt`) already calls. Their signatures are fixed; change them only together
  with the shell.
- Keeps everything else (screens, ViewModels, nested routes) inside the module, preferably `internal`.

| Feature | Route(s) | Graph entry point | Koin module |
|---|---|---|---|
| today | `TodayRoute` (object, tab root) | `NavGraphBuilder.todayGraph(navController, onOpenSession: (sessionId: String) -> Unit, onOpenNutrition: () -> Unit = {})` | `todayModule` |
| routines | `RoutinesRoute` (object, tab root) | `NavGraphBuilder.routinesGraph(navController)` | `routinesModule` |
| exercises | `ExercisesRoute` (object, tab root) | `NavGraphBuilder.exercisesGraph(navController)` | `exercisesModule` |
| progress | `ProgressRoute` (object, tab root) | `NavGraphBuilder.progressGraph(navController, onOpenSession: (sessionId: String) -> Unit)` | `progressModule` |
| session | `SessionRoute(sessionId: String)` | `NavGraphBuilder.sessionGraph(navController, onFinished: () -> Unit)` | `sessionModule` |
| nutrition | `NutritionRoute` (object, tab root) | `NavGraphBuilder.nutritionGraph(navController)` | `nutritionModule` |

Files: `feature/<name>/src/commonMain/kotlin/es/sebas1705/ironlog/feature/<name>/navigation/<Name>Navigation.kt`
(route + graph), `.../di/<Name>Module.kt`, `.../ui/<Name>Screen.kt` (placeholder to replace).

Shell behaviour features rely on:

- The shell shows a top app bar (tab title + Settings) and the bottom navigation **only on the five tab
  roots**. Nested destinations a feature adds inside its graph (`composable<MyDetailRoute> { … }`) draw
  their own `Scaffold`/`TopAppBar` with a back arrow (`navController.popBackStack()`).
- Cross-feature navigation goes through the lambdas: `onOpenSession(id)` navigates to
  `SessionRoute(id)`; `onFinished()` pops back to Today.
- The bundled catalogue is imported before the shell appears, so exercise data is always present.
- ViewModels extend `MVIBaseViewModel(initialState)` and are registered in the feature's Koin module
  (`viewModelOf(::MyViewModel)`); screens get them with `koinViewModel()`.
- UI strings go in the feature's `composeResources/values/strings.xml` (English) and
  `values-es/strings.xml` (Spanish), same keys, prefixed with the feature name. Generated class:
  `es.sebas1705.ironlog.feature.<name>.resources.Res`.
- Loads are grams (`Long`); format them with `Weights.format(grams, unit)` and the user's
  `SettingsRepository.settings.value.unit`. Times are epoch milliseconds.

What each feature fills in (spec §5, §7):

- **today**: `ObserveTodayPlan()` (active routine + `Cycle.nextPendingDay` derived from its latest session, rest-day hint), "Log past session" (`LogPastSession`), start with
  `SessionRepository.startFromRoutineDay` / `startFree`, resume with `observeInProgress`, week strip from
  `observeSessionsBetween`.
- **routines**: list (`observeRoutines`, active badge, `setActive`), editor (days/slots CRUD, reorder,
  prescription, progression), famous routines (`templates()`, `copyTemplate(id, language)`).
- **exercises**: `ExerciseRepository.search(filter, language)` with filter chips (muscle, equipment,
  category), detail (`observeExercise`, variants, `observeVariantHistory`, `Stats.personalRecords`), custom
  exercise editor (`createCustom`).
- **session**: live session on `observeSession(id)`: set rows (`logSet`, `updateSet`, `deleteSet`), prefill
  from `lastForSlotAndVariant` / `SuggestNextLoad`, plate breakdown with `PlateCalculator`, flexible-slot
  variant picker (`substituteExercise`), add/remove/move exercises, absolute-time rest timer, keep screen
  on, finish with a summary (`Stats.volume`, `Stats.newRecords`). Foreground
  service and notifications go in this module's `androidMain`/`iosMain`.
- **progress**: month calendar (`observeSessionsBetween`, "Add session on this day"), saved-session detail (edit sets in log mode, `updateTimes`, `deleteSession`), per-exercise history and charts
  (`observeExerciseHistory`, `Stats.bestOneRm`, `Stats.volume`), PR list, weekly volume per muscle.
