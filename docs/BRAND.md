# Haltera brand

Design: [docs/designs/2026-10-14-brand-design.md](designs/2026-10-14-brand-design.md).

Everything that identifies Haltera comes from one file: **[`brand/tokens.json`](../brand/tokens.json)**
(colours for light and dark, the logo geometry and the fonts). From it:

- **The app theme** (`core:ui`): `BrandColors.kt` holds the same colours and `HalteraLogo.kt` the same
  logo geometry. `BrandTokensTest` fails if either disagrees with the JSON.
- **The icons and splash** are generated by [`scripts/brand.mjs`](../scripts/brand.mjs).

## Logo: "Barbell-I"

![Haltera](../brand/logo.svg)

On a 108-unit grid (the Android adaptive-icon canvas), on a graphite `#1E2126` rounded square
(corner 24):

- the "I": a vertical bar `x=50 y=26 w=8 h=56 r=3`, iron orange `#FF5A1F`, drawn behind the beams;
- two beams `x=30 w=48 h=10 r=5` at `y=20` and `y=78`, light `#F4F4F5`;
- four plates `w=8 h=18 r=3` at `x=24`/`x=76` and `y=16`/`y=74`, iron orange, drawn on top.

The logo appears only on the launcher icon, the splash screen, the startup screen and Credits,
never inside working screens.

## Generated files

| File | Use |
|---|---|
| `brand/logo.svg` | Logo with rounded corners (documents, web) |
| `brand/icon.svg` | Full-bleed square, source of the store and iOS icons (they round it themselves) |
| `brand/icon-512.png` | Google Play listing icon |
| `composeApp/src/androidMain/res/mipmap-anydpi-v26/ic_launcher{,_round}.xml` | Adaptive icon (Android 8+): graphite background, foreground and monochrome layers |
| `composeApp/src/androidMain/res/drawable/ic_launcher_foreground.xml` | Adaptive foreground, also the Android 12+ splash icon |
| `composeApp/src/androidMain/res/drawable/ic_launcher_monochrome.xml` | Themed icon (Android 13+): the same shapes in one colour |
| `composeApp/src/androidMain/res/mipmap-{mdpi…xxxhdpi}/ic_launcher{,_round}.png` | PNG icons: Android 7 (no adaptive icons) and **Firebase App Distribution / App Tester, which cannot read adaptive icons** |
| `composeApp/src/androidMain/res/values/ic_launcher_colors.xml` | `ic_launcher_background` (graphite) |
| `composeApp/src/androidMain/res/values{,-v31}/themes.xml` | `Theme.Haltera`; on Android 12+ it sets the splash screen (`windowSplashScreenBackground` graphite, `windowSplashScreenAnimatedIcon` the foreground) |
| `iosApp/iosApp/Assets.xcassets/AppIcon.appiconset` | iOS icon, 1024 px opaque; `iosApp/project.yml` sets `ASSETCATALOG_COMPILER_APPICON_NAME: AppIcon` |

**Adaptive-icon scale.** The drawing reaches 47.2 units from the centre (the outer corner of a
plate), more than the 33-unit radius of the 66 dp safe zone. The adaptive foreground and
monochrome layers therefore scale it by **0.69** around the centre (54, 54), computed by the script,
so no launcher mask clips it. The PNG, iOS and store icons use the drawing at full size.

The Android 12+ splash uses the platform `windowSplashScreen*` attributes in `values-v31`, so no
`androidx.core:core-splashscreen` dependency is needed; older versions show the window background.

## Colours

All in `tokens.json`, light and dark. Material 3 stays the base; its roles are mapped in `Theme.kt`.

| Token | Light | Dark | Use |
|---|---|---|---|
| `accent` | `#FF5A1F` | `#FF5A1F` | Iron orange fills: logo, rest timer (`HalteraTheme.colors.accent`) |
| `onAccent` | `#1E2126` | `#1E2126` | Content on `accent` (graphite: 5.2:1, white would be 3.1:1) |
| `accentText` | `#C2410C` | `#FF5A1F` | Material `primary`: buttons, text and icons in the accent (AA on light) |
| `accentContainer` | `#FFDBCC` | `#6B2307` | Material `primaryContainer` |
| `graphite` | `#1E2126` | `#1E2126` | Icon background, dark surfaces |
| `background` / `surface` | `#F4F4F5` / `#FFFFFF` | `#141619` / `#1E2126` | Screens and cards |
| `success` / `warning` / `error` | `#15803D` / `#B45309` / `#B91C1C` | `#4ADE80` / `#FBBF24` / `#F87171` | Semantic |
| `prGold` | `#854D0E` | `#FACC15` | Personal records and the progression "↑" |
| `prGoldContainer` / `onPrGoldContainer` | `#FEF3C7` / `#713F12` | `#422006` / `#FEF08A` | `PrBadge` |

Because white text on `#FF5A1F` fails WCAG AA, Material `primary` on light is the darker
`accentText`; the pure iron orange is used for fills with graphite content.

Features read brand values that Material lacks through `HalteraTheme.colors` (`accent`, `onAccent`,
`prGold`, `success`…). `PrBadge()` is the gold "PR" pill.

## Typography

- **Barlow Semi Condensed 600** for Material display, headline and title styles and big numbers.
- **Inter 400 and 500** for body and label styles (Material letter spacing reduced, as Inter is wider
  than Roboto).
- `TextStyle.tabularFigures()` adds tabular figures (`tnum`) for loads, reps and times.

Both are OFL fonts from [google/fonts](https://github.com/google/fonts) (`ofl/barlowsemicondensed`,
`ofl/inter`), bundled in `core/ui/src/commonMain/composeResources/font/` with their licences in
`composeResources/files/licenses/`, shown in Settings → Credits. Inter is the variable font of
google/fonts (one file for both weights); Android 7 (API 24–25) cannot set variation axes and shows
weight 500 as 400.

## Changing the brand

1. Edit `brand/tokens.json`.
2. Run `node scripts/brand.mjs --png`: it rewrites the text files and renders the PNGs with a
   headless Edge or Chrome. Without `--png` only the text files are written.
3. Update `BrandColors.kt` (colours) or `LogoGeometry` in `HalteraLogo.kt` (logo) to match;
   `./gradlew :core:ui:testAndroidHostTest` (`BrandTokensTest`) shows what differs.

CI (`catalog` job) runs `node scripts/brand.mjs --check`: it fails when a generated text file is out
of date or a PNG is missing. PNG content is not compared (browser rendering is not byte-stable), so
re-run `--png` whenever the logo or its colours change.
